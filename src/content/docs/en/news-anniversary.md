## Turning "Reset" into a Rebuild

Last year's data loss erased years of work in one incident. It was a real low point — but it
forced an honest question nobody enjoys: if the data vanished again, how fast could we recover?

That answer is written across this year. Backups moved from "when we remember" to mostly
automated and off-site; key content now also lives in a static site and a remote repository; and
keeping contribution records gained a stable process. Those changes meant the later rebuild
could rest on a solid base rather than start from a hole.

## What We Added This Year

The first task was making loss recoverable. Important material no longer exists on a single
machine or in one person's account; it has known copies and a recovery path. When something needs
restoring, we know where to get it instead of searching after the fact.

The second was giving written work a home. Announcements, news, and introductions moved into
Markdown and version control; the website changed from temporary pages into a buildable static
site. Content no longer depends on a particular admin panel, which makes migration and archiving
easier.

The third was making "who did what" traceable. Events, projects, and contributions now have a
steadier record, so someone arriving later can see how something happened, not just the result.

## Continuing Is Harder Than Restoring

Fixing the system only answers "how do we avoid losing it again." The community still has to
answer "why is it worth keeping." This year, the site and docs grew back steadily, summer and
subject groups stayed active, and new divisions of work began to take shape.

We did not treat the rebuild as a sprint. We folded it into ordinary days: small changes ship
whenever they are ready, larger ones get discussed first; anything that can be written down is
written down, and anything that can be checked automatically goes to the build. It is not fast,
but each step is easier to hand over.

## A Year Later

More than "what we fixed," what matters is direction: we know better which work needs to last
and which excitement we can do without.

We don't claim the road is finished. If anything, we learned that lasting communities aren't
built on a single spark, but by folding important work into ordinary days. Thanks for walking
this year with us.

## For the Year Ahead

- Keep treating backup and recovery as something to verify regularly, not something to assume.
- Keep important writing somewhere searchable and archivable.
- Keep a clear path for new members to join and take part.
- Keep allowing slow work, but not vague work.
